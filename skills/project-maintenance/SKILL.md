# 项目维护

> 目标不是"把文件摆整齐一次"，而是让这个项目**此后每一轮工作都自动变得更可读、更可信、更好接手**。
> 判据只有一条：**治理之后，下一个接手的人（或下一个会话）少读了一半文件，却做对了更多事。**
> 参考实现：一个运行四个月的真实项目（11 条支线、21 项结构门禁、完整修正史与三次事故复盘）。本文件与具体项目无关：项目参数（路径、字段、命令、隔离规则）归项目自己，见第十一节。

## 一、理念：三种关系

### 1 · 骨架与血肉

**骨架**是每轮都要加载、极少变动、只回答"我在哪 / 该读什么 / 不许做什么"的那几件东西：入口协议、状态层、门禁、索引、技能目录、owner 表。
**血肉**是按需加载、频繁生长、承载全部内容的东西：支线文档、假设、手法、死路、决策、证据、日志。

| | 骨架 | 血肉 |
|---|---|---|
| 变动频率 | 一季一改 | 每天 |
| 加载方式 | 每轮自动进上下文 | 按需读、按指针找 |
| 形态 | 薄、稳定、可执行 | 厚、准确、可修正 |
| 典型病症 | **骨架塞血肉**：入口文件越写越厚，后来没人读得完 | **血肉上骨架**：知识散在对话和临时文件里，没人找得到 |

一条硬判据：**这条信息是"每轮都必须知道的结构/规则"吗？** 是 → 骨架。不是 → 血肉 + 一条指针。

### 2 · 分支与整体

项目必须能同时回答两个问题：整体现在在哪？某条线具体在干什么？

- **分支自治**：一条线一个"现状文件"（唯一的、机器可读的六到十个字段），加一份"人读的立项书"。分支之间不互相抄状态。
- **整体生成**：整体视图**永远由分支汇总生成，不许手写**。手写的汇总必然与实况漂移，且漂移无人负责。
- **双向流动**：
  - 分 → 总（**上浮**）：跨分支重复出现的规律，必须升到总层（假设库 / 手法库 / 负面清单）。不上浮 = 同一个坑在不同分支反复踩。
  - 总 → 分（**落回**）：总层的每条判断，必须能落回具体分支的执行动作。落不回去 = 空话，删掉。

判据：**一条规律如果只在一条分支成立，它不该在总层；在两条以上分支都成立，它必须在总层。**

### 3 · 生成性（代谢）

项目不是被"完成"的文档集，是有代谢的活体。四件事必须成机制：

| 代谢 | 机制 | 缺了会怎样 |
|---|---|---|
| **摄入** | 新证据（含失败与否定）必须有落点 | 经验停在对话里，下轮重犯 |
| **消化** | 每条新结论必须裁决为一种转换：新增 / 强化 / 纠正 / 缩限 / 取代 / 合并 / 退役 / 不动 | 只增不减，条目互相矛盾 |
| **排出** | 被推翻的条目不删，标"已被取代/退役"并留修正史 | 删了修正史 = 假装没走过弯路 |
| **生长** | 新东西先找既有位置，找不到才开新结构 | 结构膨胀，比内容膨胀更致命 |

**结构增量必须稀缺，内容增量可以很多。** 每开一个新文件、新支线、新门禁，都要问一句：能不能塞进已有的位置？结构一旦膨胀，骨架就不再是骨架。

另一个必须守住的东西：**每条判断都要写得出「什么证据能推翻它」。** 写不出的，是口号，不是判断，不收。

## 二、文档四类（写完先问自己是哪一类）

借鉴 Diátaxis：文档有四种，各有各的写法；**混写是文档病的主要来源**。

| 类型 | 回答 | 写法 | 项目里的落点 |
|---|---|---|---|
| **参考**（reference） | 是什么、有哪些字段 | 准确、完整、无叙事 | 状态文件、资产账、字段表、索引 |
| **解释**（explanation） | 为什么这样判断 | 论证 + 反例 + 推翻条件 | 假设库、决策记录、复盘 |
| **操作**（how-to） | 遇到这种情况怎么做 | 命令 + 判据 + 失败分支 | 手法库、门禁脚本、技能 |
| **教程**（tutorial） | 新人怎么上手 | 带路、给反馈点 | 入口协议的第一次怎么跑 |

落盘时同时定两件事：**落哪个 owner + 属于哪一类**。一个文件混四类，读者永远不知道该用哪种读法。

## 三、形态探测（治理前第一件事）

别拿一套模板硬套所有项目。先问五个问题，定形态，再定骨架细节：

1. 产出是什么：可运行的东西 / 一份结论 / 一批内容？
2. 工作单元是什么：模块 / 支线 / 主题？
3. 什么算"完成"：上线 / 结论落地 / 定稿？
4. 什么东西最容易腐烂：代码与文档不符 / 结论过期 / 引用断链？
5. 谁会接手：别的会话、别的同事、三个月后的自己？

三种常见形态与对应切法：

| 形态 | 分支切法 | 状态字段重点 | 知识库重点 |
|---|---|---|---|
| **交付型**（代码、产品、系统） | 模块 / 里程碑 | 构建、测试、发布、阻塞项 | 设计决策（为什么这么选）、踩坑、废弃方案 |
| **研究型**（调研、探索、验证性实验） | 支线 / 假设 | 在跑、暂停、阻塞、休眠、完结 | 假设（带置信度与推翻条件）、手法（带失效条件）、死路（带复查条件） |
| **内容型**（写作、课程、知识产品） | 主题 / 篇 | 草稿、审阅、定稿、搁置 | 论点、证据、反例、读者反馈 |

混合项目按**主产出**定形态，其余部分当附件。

## 四、骨架六件（最小实现）

| # | 件 | 回答什么问题 | 硬约束 |
|---|---|---|---|
| 1 | **入口协议**（如 `AGENTS.md` / `README.md`） | 我在哪、该读什么、不许做什么 | 每轮加载；**只放结构、规则、指针 + 一屏现状**；硬性体积上限（如 ≤12KB）；不写知识明细、不写流水、不写教程 |
| 2 | **状态层**（如 `STATUS.md` + 每分支 `STATE.md`） | 现在在哪、下一步、卡在谁 | 分支现状字段化；整体视图由分支**生成**；手写区只留战略判断（≤12 行） |
| 3 | **知识层**（分 owner） | 我们相信什么、试过什么、死了什么 | 一条知识一个 owner；每条判断带推翻/复查条件；不删旧文只标取代 |
| 4 | **门禁**（一个可执行脚本） | 结构有没有坏 | 一条命令能跑；error 阻断提交；**新发现的病要加成检查项，不是加一句提醒** |
| 5 | **索引**（生成物） | 东西在哪 | 自动生成，不手编；覆盖全仓文档；漏项算 error |
| 6 | **技能/触发层** | 什么时候该做什么 | 触发词写在 description；改流程就改技能本身，不写"注意要…" |

**入口协议的最小内容（缺一条就不合格）**：

1. **怎么跑**：装依赖、起服务、跑测试、跑门禁的确切命令（让 agent 不用猜）。
2. **怎么验**：什么算通过、失败时先看哪里。
3. **别碰什么**：不该改的目录、不该装的常驻服务、不该动的环境。
4. **去哪问**：每类问题指向哪个文件（这就是路由表）。

社区实践（`agents.md`，6 万多个开源项目在用）把它定位成给 agent 的 README / 地图：**地图不是手册**。
它不替代人类 README，也不承载知识，只保证 agent 一进来就能跑、知道边界。

**六件是职责，不是目录形状。** 下面只是一个研究型项目的实例——照抄目录是最常见的误用：

```
<项目根>/
  AGENTS.md            # 1 入口协议（薄）
  台账|docs/           # 2 状态层 + 5 索引（生成物）
    STATUS.md          #   整体现状
    DECISIONS.md       #   决策账（append-only）
    JOURNAL.md         #   工作流水（一行一天）
    INDEX.tsv          #   全仓索引（生成）
  <分支>/STATE.md      # 2 分支现状（字段化）
  <分支>/README.md     #   分支立项书与结论
  知识库.md            # 3 假设 / 手法 / 死路（可拆三文件）
  工具/                # 4 门禁脚本（render / check / new / find / log）
```

换形态就换形状：交付型常把分支做成模块目录 + 每模块一份 `STATE.md`；内容型常把分支做成主题目录加篇目清单。
**先定形态与分支切法，让目录长出来；不要先画目录再往里塞东西。**

## 五、首次治理：把乱仓库变成有机体

按序做，别跳。**每一步的产出都要能被下一步验证。**

1. **盘存量**（不改任何文件）：列出目录、文件数、最大的十个文档、最近改动的十个文档、明显重复的主题。目的是找出"实际有几条线"，而不是"文件摆在几个目录"。
2. **定形态**：用第二节五问；把现有内容归到分支切法上。归不进去的，先放"待归位"，不要急着建新支线。
3. **立骨架**：先写入口协议（薄）+ 分支现状字段 + 门禁脚本三件。门禁第一版只要三条：状态与汇总一致、索引不漏项、指针可达。
4. **迁存量**：能索引的进索引；能归位的归位；**不能判断归属的列成待裁清单**，不擅自删、不擅自合并。
5. **装代谢**：把"新结论必须裁决一种转换"和"不删旧文只标取代"写进协议，并在知识库里补上"推翻条件"字段（存量缺这个字段的，标为待补，不编造）。
6. **跑一次全绿**：门禁 0 error；再模拟一个全新接手者，只读三件（入口协议 → 状态层 → 目标分支现状），回答四个问题：现在在干什么、卡在哪、下一步最该做什么、要做这件事先读哪个文件。答不出 = 治理失败，回去改。

## 六、定期收口：六个动作

一轮工作结束时（或每周），固定走：

1. **证据账本**：这轮真实发生了什么（命令回显、文件、报错、失败原因），只记能被证明的；自我评价与推测不入账。
2. **裁决**：每条新结论选一种转换（新增/强化/纠正/缩限/取代/合并/退役/不动）；判据是证据强度与适用范围，不是"新消息更真"。
3. **落 owner**：写进唯一去处；其余地方只放指针。
4. **修机制**：这轮有没有"该自动发生却没发生"的事？有 → 改门禁、改技能触发词、改协议条款。**同一错误第二次，禁止只加笔记。**
5. **维护结构**：重生成汇总与索引；修重号、失效指针、字段缺失、状态与实况不一致；能自动修的当场修，需要方向判断的列待裁。
6. **对齐**：分支现状字段更新到今天的真实结果；整体视图重生成；待办销账；流水一行；然后门禁必须绿。

两条容易漏的：

- **复盘要分两层**：触发因素（直接起因）与根因（机制缺口）。只写触发因素，下轮还会再犯。
- **行动项要带验证方式**，否则只是愿望；决策条目用最小四字段：`背景` → `裁决` → `后果` → `取代关系`，
  且取代关系**双向**：新条目写「取代 D-0xx」，旧条目补一行「已被 D-0xx 取代」。只写单向，后来者会先读到过期结论。

## 七、上下文交接（Handoff）

会话会被清空、模型会换、上下文会满。**交接不是收尾时的补救，而是一个可以提前触发的动作。**

触发信号（任一）：上下文用掉七成以上、话题要换大方向、要切到另一个客户端、要做长任务之前。

**落盘三件（顺序不能反）**：

1. **状态层**：把这条分支的现状字段写成「现在真实的样子」，不是「计划的样子」。
2. **未完成项**：手上正在做什么、卡在哪一步、下一步的第一个动作（具体到能被直接执行）。
3. **决策与教训**：这轮新产生的裁决、被推翻的旧判断（补反向指针）、以及「别再犯」的那一条。

**再接上**：新会话只读三件——入口协议 → 整体状态 → 目标分支现状——然后回答四问；答得出就直接开工，答不出说明落盘写虚了。

**委托纪律**：把活派给子代理时，只要求它回**结论与证据位置**，不回全文；中间推理不进主上下文。这是上下文预算的另一半。

## 八、门禁：把规范变成命令

规范写在文档里，等于没有规范；**只有一条命令能把它拦下来，它才存在。**

最小可用门禁（三种检查，任何项目都能抄）：

```bash
# ① 汇总与分支现状一致（生成物过期即 error）
<render 命令> --check

# ② 索引覆盖全仓（漏项即 error）
comm -13 <(cut -f1 INDEX.tsv | sort) <(find . -name '*.md' -not -path './.git/*' | sed 's|^\./||' | sort)

# ③ 指针可达（入口协议里提到的路径必须存在）
grep -oE '`[^`]+\.(md|py|sh|tsv)`' AGENTS.md | tr -d '`' | while read -r f; do [ -e "$f" ] || echo "断链: $f"; done
```

可选外部工具（按项目性质挑，不必都上）：链接检查（lychee）、Markdown 规范（markdownlint）、
术语与语气（vale）、提交前钩子（pre-commit）；代码与文档的漂移检查通常要自己写。

加检查项的时机：**每当一个真实缺陷靠人眼才发现，就把它变成一条检查**。这是项目自我进化的主通道。

## 九、反模式诊断表（拿它给自己的项目打分）

| # | 症状 | 病根 | 修法 |
|---|---|---|---|
| 1 | 一个大文档装全项目 | 没切分支 | 按形态切，一支线一现状 |
| 2 | 汇总与实况对不上 | 汇总手写 | 改成生成物 |
| 3 | 旧结论与新闻并存、互相矛盾 | 只增不减 | 装裁决与修正史 |
| 4 | 经验散落在对话与临时文件 | 没落 owner | 定唯一 owner 表 |
| 5 | 规范写在文档里，没人执行 | 门禁缺失 | 变成命令，error 阻断 |
| 6 | 入口文件越写越厚 | 骨架塞血肉 | 明细外移，只留指针 |
| 7 | 指针指向已删文件 | 断链无人查 | 门禁加指针检查 |
| 8 | 分支之间互不引用 | 孤岛 | 强制交叉引用，孤岛进待裁 |
| 9 | 同一文件既讲原理又给命令又当索引 | 四类文档混写 | 按第二节拆开 |
| 10 | 换会话后要从头解释一遍 | 没有交接动作 | 按第七节落盘三件 |
| 11 | 读到已废止的结论、踩已经踩过的坑 | 取代关系只有单向 | 旧条目补反向指针 |
| 12 | 直接照抄别人的目录结构或示例仓 | 把职责当形状 | 先做形态探测与分支切法，再让目录长出来 |

## 十、外部参照与取舍（不是凭空发明的）

| 来源 | 采纳 | 不采纳 / 改造理由 |
|---|---|---|
| `agents.md`（6 万+ 开源项目在用） | 入口文件 = 给 agent 的地图，必须含可执行命令与边界 | 它偏代码项目的命令清单；研究型项目换成「怎么跑门禁、怎么查状态」 |
| Cline Memory Bank | 上下文交接机制：最常改的文件与里程碑文件分开；换会话前先落盘 | 固定六文件槽位与本骨架重叠，硬套会膨胀——只取机制，不取文件数 |
| Diátaxis（diataxis.fr） | 四类文档判据，治「混写」 | 它面向产品文档；项目内部文档只借分类，不搬四象限图 |
| ADR / 架构决策记录 | Status·Context·Decision·Consequences + **superseded-by 双向链** | 不采用「一条决策一个文件」；单文件 append + 反向指针已够 |
| Anthropic《Effective context engineering for AI agents》 | 上下文预算、及时检索优于预加载、结构化笔记外部化、子代理隔离 | 其工具编排与宿主绑定，不照搬 |
| GitHub Spec Kit | 工作单元三件套：意图（为什么）/ 计划（怎么做）/ 现状（做到哪） | 完整 SDD 流程（spec→plan→tasks→implement）对本类项目过重 |
| Living Documentation（Cyrille Martraire） | 生成物单一来源、文档与实现同步 | 「从测试提取文档」偏代码项目；研究型项目用门禁代替 |
| blameless postmortem / AAR | 区分触发因素与根因；行动项带负责人与验证 | 不引入其组织流程（个人项目无组织可言） |

明确不采纳：**BMAD-METHOD** 一类多角色 agent 框架（与宿主 subagent 体系重叠，会养出第二套组织）；
**Zettelkasten / PARA** 一类个人知识库方法（目标是个人记忆而非项目治理，容易让项目文档长出两套体系）。
## 十一、与具体项目的关系：方法论与项目参数分离

- 本技能只放**通用做法**。项目参数——owner 落点、分支结构、门禁命令、隔离规则、输出格式——写在该项目自己的入口协议与细则文件里。
- **进场动作**：先读项目根的入口协议（`AGENTS.md` / `README.md`）→ 顺它指向的细则文件读 → 没有细则就按第四节立骨架，并把参数写进该项目。
- 参考实现：一个运行四个月的真实项目——入口协议 + 状态层 + 假设/手法/死路三库 + 决策账 + 生成式索引 + 21 项门禁 + 修正史与事故记录；该项目的参数写在它自己的收口手册里，不在本技能里。
- 一条硬规矩：**换项目只换手册，不换技能**。如果某个项目的参数非改技能不可，那是方法论的缺口——改这里，别在项目里开例外；反之，别把项目特例回填成通用条款。

## 十二、输出（治理完成时给这六段）

1. **形态判定**：这是什么形态的项目、分支怎么切、依据是什么
2. **骨架现状**：六件各自有没有、质量如何（缺失的列出来）
3. **本轮治理动作**：改了什么、为什么、影响了哪些文件
4. **待裁**：需要人判断的（合并/删除/退役/方向），一句一条
5. **门禁结果**：命令、退出码、剩余 error 与 warn 及原因
6. **接手验证**：模拟新会话只读三件后的四问四答，答不出的地方就是下一步

## 十三、硬规则

1. **治理的判据是"下一个人少读一半、做对更多"，不是"文件看起来整齐"。**
2. **骨架薄而稳，血肉厚而准**：入口文件只放结构、规则、指针；知识一律有 owner。
3. **汇总永远生成，永不手写。**
4. **一条知识一个 owner**；其余地方只放指针。
5. **结构增量稀缺，内容增量随便**：开新结构前先问能不能塞进老位置。
6. **不删旧文**：标取代/退役 + 修正史。
7. **每条判断写得出推翻条件**，写不出不收。
8. **新缺陷 → 新检查项**，不是新提醒。
9. **一份文档只做一类事**（参考 / 解释 / 操作 / 教程），混写就拆。
10. **上下文将满先落盘，再做别的**；交接三件（现状 / 未完成 / 下一步）写不出等于没交接。
11. **需要方向判断的事列待裁**（合并、删除、退役、资源投入），不代裁。
12. **门禁不绿不算完成**；如实报哪条红、为什么。
13. **秘密只进隔离目录**，文档只写位置与指纹。
14. **不把项目知识写进外部知识库**，除非该项目明确允许——默认不出仓。
