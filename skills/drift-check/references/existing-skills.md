# 参考：现有的「漂移 / 对齐」类技能（2026-11 检索）

这份早期笔记记录当时选取的几种改动审查方法及其设计启发。它只覆盖表里的样本。现行工作方法以 [SKILL.md](../SKILL.md) 为准。

| 技能 | 它问的问题 | 单位 | 可借的 |
|---|---|---|---|
| `ninehills/skills` · `check` | 这个 diff 和声明的目标对得上吗？ | 一次改动 | 「每个新增的公共面都要能用一句话追溯到目标，否则先判为漂移」 |
| `shauryagangrade/intent-drift-skill` | 目标 / 计划 / 文件改动之间漂了多少 | 一个任务 | 「证据优于叙述」：每条判断落到可核的行；只产出暂停并确认；默认脱敏 |
| `tomzx/agents` · `validate-pr` | 我们造的是对的产品吗？ | 一个 PR | **恢复需求，而不是复述验收标准**——标准本身也可能是错的靶子 |
| `freenet/freenet-agent-skills` · `big-picture-reviewer` | PR 是真解决问题，还是在追 CI 绿灯 | 一个 PR | 「症状修复」的清单；以及「AI 指令也会过期」这条 |
| `fullsend-ai/agents` · `intent-coherence` | 有没有授权、有没有夹带 | 一个 PR | 范围分类法（scope-creep / unauthorized / over-engineering ……） |
| `archive228/loopkit` · `adversarial-verify` | agent 假装「做完了」的 11 种捷径 | 一次任务 | 检查完成声明如何被证据支持 |

## 共同结构（值得照抄）

- **外部锚**：issue / PR / 任务描述。有锚才能判偏。
- **只读**：审计不改东西。
- **证据行**：不接受「我认为对得上」。
- **暂停并确认**：不自动决策。
- **有明确的「不该用」边界**：`validate-pr` 开头就写「它不构建、不运行、不判工艺」。

## 在方向判断中的用法

漂移检查关注一段时间里的工作是否仍在支持负责人确认的目标。单次改动审查的证据可以纳入这种判断。需要独立复核时，先让复核者从原始材料形成判断，再对照理由。
